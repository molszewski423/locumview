# FIPS mode and RDP sign-in: test record (2026-10-19)

Evidence for ADR 0012. Test VM booted from the LocumView bootc image (changelog #52) on node1's libvirt NAT network;
GNOME Remote Desktop 49 in user mode on port 3390, configured by `packaging/remote-access/user-mode-user.sh` with
throwaway credentials; client FreeRDP 3.15 on node1, authentication only:

```
xfreerdp3 /v:<test-vm>:3390 /u:<user> /from-stdin:force /cert:ignore /sec:nla +auth-only     # password on stdin
```

| Image | `fips_enabled` | Crypto policy | Result |
|---|---|---|---|
| FIPS mode on (`fips=1`) | 1 | FIPS | **Fails**: `ERRCONNECT_AUTHENTICATION_FAILED` |
| FIPS mode off | 0 | DEFAULT | **Succeeds**: `Authentication only, exit status 1` (FreeRDP's success code), process exit 0 |

The FIPS run was repeated after a rollback (`bootc rollback`) with the username passed as an argument, after the first attempt had fed the credential prompts in the wrong order. Server log of the repeated run (gnome-remote-desktop-daemon):

```
[ERROR][com.winpr.crypto.hash] - [winpr_Digest_Init_Internal]: Failed to initialize digest md4
[WARN][com.freerdp.core.rdp] - [log_build_warn_hash]:  * md4: NTLM support not available
[WARN][com.winpr.sspi] - [winpr_AcceptSecurityContext]: AcceptSecurityContext status SEC_E_MESSAGE_ALTERED [0x8009030F]
[ERROR][com.freerdp.core.auth] - [credssp_auth_authenticate]: AcceptSecurityContext failed with SEC_E_MESSAGE_ALTERED [0x8009030F]
[ERROR][com.freerdp.core.transport] - [transport_accept_nla]: client authentication failure
```

With `/sec:tls` instead of NLA the server refuses outright: `server supports only NLA Security` (client: `HYBRID_REQUIRED_BY_SERVER`).

Second FIPS effect seen in the same test: `sshd -T` lists only ECDSA in `pubkeyacceptedalgorithms` and `hostkeyalgorithms`, so Ed25519 keys are refused.
