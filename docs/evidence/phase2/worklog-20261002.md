# Phase 2 worklog, 2026-10-02

Chronological record of every decision and command in the move to MikePC and the start of Phase 2. Summarised in changelog #15 onward. Times are EDT.

## Decisions (owner: Michael Olszewski)

- **VM host: MikePC.** Most CPU and RAM in the homelab (Ryzen 7 7800X3D, 8 cores, SMT off; 30 GiB RAM; RTX 5060 Ti + Raphael iGPU), wired NIC, already the k3s control plane. Replaces the ThinkPad, which is on Wi-Fi (Wi-Fi can't be bridged) and whose libvirt NAT network is unreachable from the k3s nodes, so guacd could not reach the desktop.
- **GPU not passed through.** GNOME Remote Desktop renders in software in a headless session, and passthrough would take the RTX away from the k3s Ollama workload, where local-LLM features belong. Revisit only for GPU workloads inside a desktop.
- **Access layer on k3s** (ADR 0002) and **secrets with SOPS + age** (ADR 0003): proceed, provided every step is documented for compliance.

- `export-thinkpad.sh` (root, ThinkPad): records the definition and snapshot XML; shuts the VM down gracefully (never destroys it); disables autostart; copies the disk's active layer with `qemu-img convert` (internal snapshots not migrated, see Discovery); converts the NVRAM from qcow2 to raw; tars the swtpm state; writes SHA256SUMS. - Transfer: `rsync -S` as mike, from `/home/mike/locumview-export/` to `mikepc:/home/mike/locumview-import/`.

Each script writes its own log (`export.log`, `import.log`), which is copied to `docs/evidence/phase2/`.

Known interim exposure: on br0 the guest's RDP port (firewalld `rdp` service, public zone) can be reached from the whole home LAN, not just through libvirt NAT. Accepted until guacd is up; then RDP gets restricted to the k3s node addresses (the changelog #4 follow-up).

## 12:15 Decisions: public domain, Nextcloud, identity (owner: Michael Olszewski)

- **locumview.com** (owned by Mike, DNS on Cloudflare) is the public entry point. It is reached through a **Cloudflare Tunnel** (cloudflared running in k3s, outbound-only): no inbound ports on the home router, and RDP never published. Order of work: nothing is published on the domain until Guacamole sits behind Keycloak with MFA enforced.
- **Nextcloud runs on k3s** beside Guacamole, not inside the desktop VM. Desktops are rebuildable and will become per-user, so a shared, stateful file server inside one would break that. Desktops reach users' files over WebDAV.
- **Keycloak is the single identity provider.** Organizational accounts (with MFA) live in Keycloak. Guacamole, Nextcloud and later the desktops are OIDC clients. Nextcloud is not the user directory.
- ADR 0004 (public access through Cloudflare Tunnel) and ADR 0005 (Keycloak as IdP; Nextcloud as an OIDC client on k3s) are to be written before the first internet-facing deployment.
