# PHP "php2shell" (CVE-2026-109618, CVE-2026-109619): exposure check, 2026-10-22

On 2026-10-21 the PHP project released fixes for two critical flaws in the PHP interpreter: CVE-2026-109618 (memory
corruption in out-of-memory handling) and CVE-2026-109619 (use-after-free across requests), both CVSS v4.0 9.2,
unauthenticated remote code execution through mod_php and PHP-FPM, exploited in the wild. Fixed in PHP 8.5.12,
8.4.27, 8.3.36 and 8.2.35; 8.1 and earlier get no official fix. Sources: the PHP Foundation's release post
(https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security/),
Rapid7 (https://www.rapid7.com/blog/post/etr-cve-2026-109618-and-cve-2026-109619-critical-unauthenticated-remote-code-execution-in-php/),
Tenable (https://www.tenable.com/blog/php2shell-cve-2026-109618-cve-2026-109619-frequently-asked-questions-about-critical-php-remote).

## Result

**LocumView does not run PHP anywhere, so no patch is needed today.** Checked 2026-10-22, read-only:

| Where | How | PHP |
|---|---|---|
| Desktop image in production (`sha256:137e69fa…`) | `rpm -qa 'php*'`, `command -v php php-fpm` in the image | none |
| Live demo desktop (lv-demo01) and the reference desktop | the same, on each desktop | none |
| node1, node2 (Debian 13) | `dpkg -l 'php*' 'libapache2-mod-php*'`, `command -v php` | none |
| idm01 (IdM server) | `rpm -qa 'php*'` | none |
| dev-laptop-2 (operator machine) | `rpm -qa 'php*'` | none |
| dev-laptop-1 (openSUSE Leap 16) | `rpm -qa 'php*'`, `command -v` for the PHP binaries (run by the owner, later the same day) | none |
| k3s: every running container (38 distinct images: LocumView's access layer, Gitea, CI runner, monitoring, and the other workloads on the cluster) | in each container, a search for `php`, `php-fpm`, `php-cgi`, `php8*` and PHP's install directories; containers without a shell are single static binaries (Go) | none |
| k3s: deployments scaled to zero (could be started again) | base images from their build files | Python, Node, nginx, Postgres images: none |
| Website (locumview.com) | Next.js on Cloudflare; PHP files in the repository | none |

A desktop cannot gain PHP at runtime either: on an image-mode desktop `/usr` is read-only, so software arrives only
through a new signed image, which the image scan and the package list (SBOM) would show.

## What it means for the plan

- **Phase 9 lite's mock EHR, OpenEMR, is a PHP application.** When it is built, it must run on a PHP release with
  these fixes (8.3.36, 8.4.27, 8.5.12 or later on the branch it uses), and its container image is to be covered by
  the same check. Recorded in `docs/PLAN.md` (Phase 9 lite).

## How to repeat this check

For the next advisory: the image's package list (SBOM attestation on every signed image) and `rpm -qa` on the
desktops; `dpkg -l` or `rpm -qa` on the nodes; a search inside every running container; the build files of
deployments scaled to zero. Nothing in the check changes a system.
